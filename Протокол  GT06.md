# Frame Format

GT06 packets are binary TCP packets.

Common frame:

```text
78 78
Length
Protocol Number
Payload
Serial Number
CRC16
0D 0A
```

Long-frame variants may use:

```text
79 79
Length 2 bytes
Protocol Number
Payload
Serial Number
CRC16
0D 0A
```

For current device, observed packets use:

```text
78 78 ... 0D 0A
```

---

# Basic Structure

```text
Start Bit        2 bytes   78 78
Length           1 byte
Protocol         1 byte
Information      N bytes
Serial Number    2 bytes
CRC16            2 bytes
Stop Bit         2 bytes   0D 0A
```

Length usually counts bytes from `Protocol` through `Serial Number`.

CRC16 is calculated over:

```text
Length + Protocol + Information + Serial Number
```

Not including:

```text
78 78
CRC16
0D 0A
```

# Observed Packet Types

## 0x22 — GPS / Location Packet

Observed example:

```hex
78 78 22 22 1A 06 06 13 38 2A CB 04 A3 5F EC 08 3F 23 BC 03 14 FB 01 91 02 33 D9 00 52 78 00 00 00 03 17 88 BD 0D 0A
```

Structure:

```text
78 78               start
22                  length
22                  protocol = GPS/location
1A 06 06 13 38 2A   date/time
CB                  GPS info + satellite count
04 A3 5F EC         latitude
08 3F 23 BC         longitude
03                  speed
14 FB               course/status
01 91               MCC
02                  MNC
33 D9               LAC
00 52 78            Cell ID
00 00 00 03         unknown / ACC / status / mileage extension
17 88               CRC16
BD                  extra / checksum-like byte in observed stream
0D 0A               end
```

Note: observed stream contains packets concatenated together, and some frames may include extra vendor fields. Parser must split by valid `78 78 ... 0D 0A` frames and validate by length.

# GPS Time

Time is BCD-like, 6 bytes:

```text
YY MM DD HH MM SS
```

Example:

```hex
1A 06 06 13 38 2A
```

Decode:

```text
YY = 0x1A = 26
MM = 0x06 = 06
DD = 0x06 = 06
HH = 0x13 = 19
MM = 0x38 = 56
SS = 0x2A = 42

2026-06-06 19:56:42
```

Important: GT06 commonly sends UTC time. Some firmware may apply local timezone. Compare with server log time.

# Latitude / Longitude

Coordinates are 4-byte unsigned integers, big-endian.

Formula commonly used by GT06:

```text
decimal_degrees = raw / 30000 / 60
```

Equivalent:

```text
decimal_degrees = raw / 1800000
```

Example latitude:

```hex
04 A3 5F EC
```

Raw:

```text
0x04A35FEC = 77815788
```

Decode:

```text
77815788 / 1800000 = 43.230993
```

Example longitude:

```hex
08 3F 23 BC
```

Raw:

```text
0x083F23BC = 138355644
```

Decode:

```text
138355644 / 1800000 = 76.864247
```

Result:

```text
43.230993, 76.864247
```

# Course / Status

2 bytes.

Example:

```hex
14 FB
```

Contains:

* course angle
* GPS positioning flag
* latitude hemisphere
* longitude hemisphere
* real-time/differential flags

Basic approach:

```text
course = value & 0x03FF
```

For:

```hex
14 FB
```

Raw:

```text
0x14FB
```

Course:

```text
0x14FB & 0x03FF = 251°
```

Other bits should be decoded separately later.

# 0x13 — Heartbeat / Status Packet

Observed example:

```hex
78 78 0A 13 44 06 02 00 01 03 1A ED 12 0D 0A
```

Structure:

```text
78 78       start
0A          length
13          protocol = heartbeat/status
44          terminal information
06          voltage level
02          GSM signal strength
00 01       alarm/language/status field
03 1A       serial number
ED 12       CRC16
0D 0A       end
```

Server must respond with ACK.

ACK format:

```hex
78 78 05 13 <serial_hi> <serial_lo> <crc_hi> <crc_lo> 0D 0A
```

Example for incoming serial:

```hex
03 1A
```

Response body before CRC:

```hex
05 13 03 1A
```

Full ACK:

```hex
78 78 05 13 03 1A <CRC16> 0D 0A
```

# 0x01 — Login Packet

Common GT06 login packet format:

```text
78 78
0D
01
IMEI 8 bytes BCD
Serial 2 bytes
CRC16 2 bytes
0D 0A
```

Example shape:

```hex
78 78 0D 01 03 52 67 21 08 48 76 12 00 01 CRC CRC 0D 0A
```

Server response:

```hex
78 78 05 01 <serial_hi> <serial_lo> <crc_hi> <crc_lo> 0D 0A
```

If no login packet is seen, device may resume cached session or send location packets directly after reconnect.

# Server ACK Rules

For most GT06 packets requiring acknowledgement:

```text
78 78 05 <protocol> <serial_hi> <serial_lo> <crc_hi> <crc_lo> 0D 0A
```

Where:

```text
protocol = same protocol number as incoming packet
serial   = serial number from incoming packet
crc      = CRC16 over 05 + protocol + serial
```

Observed important ACKs:

```text
Incoming 0x01 login      → ACK 0x01
Incoming 0x13 heartbeat  → ACK 0x13
```

Some location packets may not require ACK depending on firmware and mode. If the device repeats location packets aggressively, send ACK using same rule:

```text
Incoming 0x22 location → ACK 0x22
```

Format:

```hex
78 78 05 22 <serial_hi> <serial_lo> <crc_hi> <crc_lo> 0D 0A
```

# CRC16

GT06 uses CRC-16/X25-like algorithm in many implementations.

Common parameters:

```text
poly: 0x1021
init: 0xFFFF
xorout: 0xFFFF or 0x0000 depending on implementation
input reflected: sometimes yes
```

Do not guess blindly. Validate CRC implementation against observed frames.

Known observed heartbeat:

```hex
78 78 0A 13 44 06 02 00 01 03 1A ED 12 0D 0A
```

CRC input likely:

```hex
0A 13 44 06 02 00 01 03 1A
```

Expected CRC:

```hex
ED 12
```

Use this as test vector.

# Minimal Server Implementation

Required:

1. TCP listener.
2. Buffer incoming bytes.
3. Split stream into GT06 frames:

   * start `78 78`
   * length byte
   * expected full frame length:

     ```text
     2 + 1 + length + 2
     ```

     where:

     ```text
     2 = start bytes
     1 = length byte
     length = protocol + payload + serial + crc
     2 = stop bytes 0D 0A
     ```
4. Validate stop bytes `0D 0A`.
5. Validate CRC16.
6. Decode:

   * `0x01` login
   * `0x13` heartbeat/status
   * `0x22` location
7. Send ACK:

   * `0x01` → ACK
   * `0x13` → ACK
   * optionally `0x22` → ACK
8. Store location data:

   * IMEI
   * time
   * latitude
   * longitude
   * speed
   * course
   * MCC/MNC/LAC/Cell ID
   * raw packet hex

# Important Difference From JT/T808

JT/T808:

```hex
7E ... 7E
```

GT06:

```hex
78 78 ... 0D 0A
```

JT/T808 ACK:

```hex
7E 80 01 ...
```

GT06 ACK:

```hex
78 78 05 <protocol> <serial> <crc> 0D 0A
```

Do not mix these protocols.
